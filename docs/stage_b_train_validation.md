## model.train() 和 model.eval() 有什么区别？

它们用于切换模型及其子模块的运行模式：

| 调用 | 含义 |
|---|---|
| model.train() | 切换到训练模式 |
| model.eval() | 切换到评估模式，相当于 model.train(False) |

它们本身不会执行 forward，也不会自动开始训练或更新参数。

模式切换主要影响某些在训练和评估时行为不同的层。例如：

- Dropout：训练时随机将部分特征置零；评估时停止随机丢弃。
- BatchNorm：默认配置下，训练时使用当前 batch 的统计量并更新运行统计量；评估时使用已保存的运行统计量。

目前我的模型只有 Linear 和 ReLU，这些层在 train/eval 两种模式下计算行为相同。设置模式是为了让训练与评估流程明确，并为以后使用其他层做好准备。

## 模型模式与梯度是两件不同的事

我之前容易把“进入训练模式”理解为“开始训练”，或者把“进入评估模式”理解为“关闭梯度”。

实际上：

| 操作 | 作用 |
|---|---|
| model.train() | 设置训练模式 |
| model.eval() | 设置评估模式 |
| torch.no_grad() | 暂时关闭梯度记录 |
| loss.backward() | 根据计算图计算梯度 |
| optimizer.step() | 根据梯度和优化器规则更新参数 |

因此：

- model.train() 不会自动计算梯度或更新参数。
- model.eval() 不会自动关闭梯度。
- torch.no_grad() 不会自动把模型切换到评估模式。

验证时通常同时使用 model.eval() 和 torch.no_grad()：前者设置层的行为，后者避免记录不需要的计算图。

如果之后继续训练，需要重新调用 model.train()。退出 no_grad 的代码块后，梯度记录会恢复到进入前的状态，但模型模式不会自动切回训练模式。

## 验证是不是很像 inference？



> 验证理论上是不是很像 inference？

是的，验证的核心就是 inference，再加上与真实标签比较、统计指标。

- Inference：输入图片，得到预测，不要求提供真实标签。
- Validation：输入图片，得到预测，再用真实标签计算 loss 和 accuracy。

验证需要标签来评分，但不使用这些标签更新模型参数。

本次验证使用训练结束后的同一个 model，没有重新创建模型，没有执行 backward 或 optimizer.step()。

## DataLoader 的返回顺序

    for images, labels in val_set:

val_set 每次返回一对数据：

    (一批图片, 一批标签)

Python 按位置赋值，不会根据变量名字匹配内容。第一个变量接收图片，第二个变量接收标签。

模型接收的是当前批次的 images，而不是 DataLoader 对象 val_set。

## 验证指标如何累计

验证开始前，将累计正确数量、累计样本数量和累计 loss 清零。

每批执行：

1. Forward，得到 [B, 10] 的 logits。
2. 使用 argmax(dim=1) 得到 [B] 的预测类别。
3. 与 labels 比较，累加正确数量。
4. 累加实际样本数 labels.shape[0]。
5. 累加 batch 平均 loss × 当前 batch 样本数。

完整遍历后：

    accuracy = 累计正确数量 / 累计样本数量
    average_loss = 累计 loss 总和 / 累计样本数量

最后一批不足 32 张时，也按实际样本数统计。本次验证共 188 个 batch，最后一批为 16 张，累计样本数确认为 6,000。
