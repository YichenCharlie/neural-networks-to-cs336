# Stage C 学习笔记：从字符编码到 Bigram 语言模型

这一阶段我用 `"hello world"` 写了一个字符级 Bigram（二元语言模型）。给它一个字符，它会为词表里的每个字符打分，预测谁最可能出现在下一位。最后，我把字符编码、随机取 batch、训练、逐位置预测和自回归生成写进了同一个脚本：[`scripts/stage_c_bigram.py`](../scripts/stage_c_bigram.py)。

## 1. 从一句话得到训练数据

`"hello world"` 含空格共 11 个字符，去重后有 8 种。把字符排序，再建立 `stoi`（字符 → ID）和 `itos`（ID → 字符），就能在文本和整数之间来回转换。

```text
字符： ' '  d  e  h  l  o  r  w
ID：    0   1  2  3  4  5  6  7

hello world → [3, 2, 4, 4, 5, 0, 7, 5, 6, 4, 1]
```

要构造训练数据，不需要另外标注答案。把原文错开一位，同一列就组成一道“预测下一个字符”的题：

```python
x = encoded[:-1]  # 'hello worl'
y = encoded[1:]   # 'ello world'
```

第一题是 `h → e`，最后一题是 `l → d`。11 个字符一共提供 10 对相邻字符。这里的 ID 只是编号，`o` 的 ID 比 `l` 大，并不代表它的分数更高。

## 2. 为什么模型是一张 8 × 8 的表？

> “为什么是8 * 8的表格，你不是说行是输入，列是输出吗，那不应该是10 * 10吗”

我当时混淆了**有多少道题**和**每道题有多少个候选答案**。10 是这句话提供的预测位置数；8 是词表大小。模型需要为 8 种可能的当前字符各准备一行，每一行又要给 8 种候选后继字符打分，所以是 `8 × 8 = 64` 个可训练参数。换一段更长的文本，只要词表没变，参数量也不会变。

> “我很好奇，pytorch自带的这个embedding是什么模型可以这样训练，还是就是单纯是个词表的索引表”

`stoi` 是固定字典，`nn.Embedding` 是**可以训练的查找表**。例如 `stoi["l"]` 告诉我去第 4 行，`table.weight[4]` 才是训练过程中会改变的 8 个数。在这个特定模型里，这 8 个数直接作为 logits（原始分数），每一列对应一个候选字符。训练时交叉熵接收 logits；想查看概率或采样时，再做 softmax。

在最初用完整文本训练的 Notebook 实验中，输入 `l` 后，`l`、`o`、`d` 的概率都约为 `0.311`。回头看原文就能解释：三个 `l` 的下一位分别是 `l`、`o`、`d`，各出现一次。模型每次看到 `l` 都查同一行，学到的是一个分布。

## 3. 怎样从连续文本里取一个 batch？

> “我没太懂为什么要学这个，这个是在干嘛，为什么要写这个”

做 Fashion-MNIST 时，一张图片天然就是一条样本；现在拿到的是一串连续字符，需要自己决定每一步取哪几段，以及每段的答案在哪里。这次设 `B = 2`、`T = 4`：每批抽两段，每段做四次预测。为了让第 4 个位置也有答案，每段实际要取 **`T + 1 = 5` 个字符**。

以起点 `6` 为例，这已经是 `"hello world"` 最靠右的合法起点：

| 操作 | 解码结果 | 用途 |
|---|---|---|
| 取连续 5 个字符 | `'world'` | 原始窗口 |
| `window[:-1]` | `'worl'` | 四个输入 |
| `window[1:]` | `'orld'` | 对应的四个目标 |

> “这个start为什么是抽出来，【5，5】，还有啊这个window【：-1】切出来的是哪一块啊”

`torch.randint(0, len(encoded) - T, size=(B,))` 在这个例子里从 `0` 到 `6` 抽两个起点，允许重复。因此 `[5, 5]` 表示这批恰好抽到了两次相同的窗口，不是程序出错。起点 `5` 对应空格，窗口为 `' worl'`，`[:-1]` 去掉最后的 `l`，得到 `' wor'`；`[1:]` 去掉开头的空格，得到 `'worl'`。

随机的是**片段的起点**，片段内部一直保留原文顺序。每步换一批，改变的是哪些样本参与本次更新。`T = 4` 允许一起计算四个位置的损失，但 Bigram 在每个位置仍然只看当前一个字符。

## 4. 为什么要 reshape？一个字符的 loss 怎么算？

> “所以这个btv到底分别是什么意思，我们为什么要将多条输入平摊开来，为什么又要将结果平摊开来”

| 张量 | 本次 shape | 怎么读 |
|---|---|---|
| `x_batch`、`y_batch` | `[2, 4]` | 2 个片段，每段 4 个位置，每个位置存一个字符 ID |
| `table(x_batch)` | `[2, 4, 8]` | 每个位置都得到词表中 8 个字符的分数 |
| `logits.reshape(-1, vocab_size)` | `[8, 8]` | 8 道预测题，每行保留一道题的全部分数 |
| `y_batch.reshape(-1)` | `[8]` | 按相同顺序排列的 8 个正确答案 |

`B` 是 batch size，`T` 是 sequence length，`V` 是 vocabulary size。输入 `[B,T]` 可以直接查表；计算交叉熵时，再把 logits 的前两维合并成 `[B*T,V]`。`-1` 表示让 PyTorch 根据元素总数推断这一维。本例中 `B*T` 和 `V` 碰巧都等于 8：**输出展开后的 `[8,8]` 是八道题的分数，参数表的 `[8,8]` 是八种输入字符的权重。** 有多个位置输入 `l` 时，输出里会重复出现同一行。

> “这个字符的损失又是怎么算的呢，我可以理解为单纯的概率减减吗，但是目标y不是只有一个数字对应的字符吗”

只传一个 ID 就够了。比如 `h → e` 的目标是 `2`，意思是“第 2 列是正确答案”。如果 softmax 后模型给 `e` 的概率是 `0.6`，这个位置的损失就是 `-ln(0.6) ≈ 0.511`。模型给真实字符的概率越高，这一项损失越小。默认情况下，batch loss 是所有预测位置损失的平均值。

代码中直接写 `loss_api(flat_logits, flat_target)`：**分数在前，标签在后**。`CrossEntropyLoss` 自己完成从 logits 到损失的计算，不需要先手动 softmax。

## 5. 训练结果：用同一组题比较前后变化

独立脚本使用 SGD，学习率 `0.1`，训练 `1,000` 步。模型和优化器只在循环前创建一次，随机 batch 在每一步重新抽取。训练前后都在原文的全部 10 对相邻字符上计算平均交叉熵。

| 独立脚本的一次运行 | 结果 |
|---|---:|
| 词表大小 / 可训练参数 | 8 / 64 |
| 初始 full-text loss | 2.067232 |
| 最终 full-text loss | 0.647340 |
| 逐位置取最高分的命中数 | 7/10 |

这次第 800 步的 batch loss 是 `0.4225`，第 1,000 步是 `0.5945`。因为两步的题目可能不同，仅看这两个数不能判断模型变好了还是变差了。完整文本上的 loss 从 `2.067232` 降到 `0.647340`，才是在相同题目上的前后对照。这里衡量的是对训练文本的拟合，不是对新文本的泛化。

## 6. 逐位置检查和自回归生成有什么区别？

> “我想问一下自回归生成是干嘛的，为什么要这样子搞，直接看结果不是一样的吗”

我最后保留了两种输出。它们的区别在于：**下一步的输入由谁提供？**

**逐位置检查：每一步都从原文取输入。** 对 `text[:-1]` 的每个字符取 `argmax`，再和 `text[1:]` 对齐，就能看到具体错在哪里：

```text
输入：'hello worl'
真实：'ello world'
预测：'eloo wo lo'
```

这次猜对了 7/10，而且这就是当前 Bigram 在这段文本上使用固定 `argmax` 能达到的上限。三个 `l` 各有不同的后继，模型三次只能给出同一个答案，至少错两次；两个 `o` 后面分别是空格和 `r`，至少再错一次。这三处错误来自模型只能看当前字符的限制。

**自回归生成：只给一个开头，后续输入来自模型自己。** 从 `'h'` 开始，把当前行的 logits 转成概率，用 `torch.multinomial` 抽取一个 ID。将抽到的字符追加到结果，作为下一步的输入，重复 20 次：

```text
Generated: 'heldrlo wo wordeweldl'
Length: 21
```

这里最能说明问题的是 `'held'`：当模型写出 `d` 后，下一步就根据 `d` 继续生成，不会回到原文去读 `l`。这也是我从分类任务转到语言模型时真正理解的一点：**有原文时，我可以逐位判断对错；只有开头时，模型要自己决定接下来写什么。** 生成结果不需要复刻 `"hello world"`。是否自回归，取决于有没有把自己的输出送回下一步；用采样还是 `argmax`，是另一个选择。

> “我理解了！所以理论上我让他会生成什么只是我的思维惯性了，还困在当初的分类正确或错误，而在语言模型中，只有开头，剩下都要看模型生成的质量，不是仅仅前面跟着后面”
